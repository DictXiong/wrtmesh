# wrtmesh v6.4.0

Peer setup now selects actual SSIDs with checkboxes. Local controllers are
prepared automatically; manual profile IDs and BSSID lists are no longer part
of the UI. Multiple radios can share the same SSID when their service and
security settings agree. Internal names may differ across APs.

BSSID and MLO link changes arrive through the existing cached peer snapshots.
The management LAN IP/MAC binding, exact SSID, source age, report structure and
application generation are validated. Frozen or conflicting reports expire
and are removed. Configuration writes remain authenticated local RPC only;
passwords, keys and credential hashes are never sent to peers.

The Mesh page displays status per peer and selected SSID. “Roaming enabled”
means current validated neighbor information has been applied to hostapd.
Pending, stale, identity/security mismatch and unsupported-peer states explain
why the relationship is not active. Older pinned configurations remain
supported; automatic SSID roaming requires a capable peer.

Overview and Mesh client labels now fall back from hostname to IPv4, then
IPv6, and use `?` only when no identity or address is known. Timers are kept
under advanced settings. Native LuCI includes and package file ownership
remain unchanged.
